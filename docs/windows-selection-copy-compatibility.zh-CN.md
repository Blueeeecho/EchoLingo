# Windows 取词方式

用户的操作保持为：选中文字 → 按 Alt+D → 自动取得文字、弹框并翻译。辅助功能选区是应用间的后台接口，不是一次用户操作或新增授权。若它返回真实选区，严格模式直接使用；视觉上的高亮不保证该接口一定返回文字。

2026-10-28按机主选择，Windows 默认使用“复制兼容”。程序在来源窗口仍有焦点时模拟一次 Ctrl+C，读取这次复制结果，尝试恢复原剪贴板，再显示翻译框。完整 UIA 树或 RuntimeId 不再是这条路径的前提。设置 → Windows 取词中可切换“严格识别”。旧配置未填写此字段时使用 copy，显式 auto 仍尊重。macOS 取词路径不变。

保留的保护包括：来源原生窗口/焦点一致、单次注入、剪贴板版本与发布来源核对、取消和原有内容恢复。原生 Edit/RichEdit 使用完整32位选区及密码检查；通用控件仅作有界密码元数据检查，未知状态不等于已证明无密码。部分代码编辑器空选区时 Ctrl+C 会复制整行，需严格识别时请切换模式。无法安全保存复杂剪贴板格式或验证独立发布进程时，程序可能停止取词；不隐瞒恢复失败。

诊断只保留18个有界数值 copy 字段，以及本进程 attempt/阶段/结果是否为空。每次 Alt+D 开始便重置，即使尚未启动 helper，也不会显示上一轮结果；旧任务迟到的诊断不会覆盖新轮。记录不包含原文、窗口标题、clipboard文本或凭据。phase4至phase5之间尚未细分所有丢弃原因，不能据此声称已确认全部现场根因。

当前验证按分层记录：完整编译/纯策略、隔离界面、独立原生Windows夹具、实际程序快捷键、真实安装器及目标Win10/11应用分别验收。GitHub-hosted Windows桌面不是机主的实体WPS/Google网页；旧候选空框外部点击通过也不能覆盖机主报告。最新结果见status.md与test-report.md。
