# EchoLingo Windows 实机验收计划

日期：2026-10-24。适用：0.1.0 及其修复预览版。目标：确认安装后的完整桌面链路，而不只验证源码能编译。

**本文件是待执行计划，不是通过报告。** Windows CI、原生helper夹具、ARM虚拟机和x64实机各有覆盖范围。未运行的用例填写“未运行”，没有对应设备填写“环境缺失”，不能填通过。本计划不要求购买、安装或推荐虚拟机产品。

## 2. 测试前准备

使用专门的测试Windows账户或可回滚测试环境，所有输入均为虚构内容。若VM开启主客共享剪贴板，剪贴板竞态测试期间应临时关闭共享或记录其影响，防止宿主同步造成假阳性。

准备记事本、浏览器普通网页/输入框、VS Code（若日常使用）、Office/其他文档编辑器（若已有）、可选择文本的PDF查看器。不得为了跑本计划默认安装付费软件；缺少软件如实记录。

准备三类测试内容：

- 可选文本：`EchoLingo 回声译 日本語 2468`，多行段落、emoji、数学符号、引号、反引号、美元符、`$(echo TEST_ONLY)` 等；后者应始终是数据，不能作为命令执行。
- 清晰图像：英文、简体中文、混排、浅色/深色背景、小字号、双栏、空白图；记录期望文字和图像尺寸。可以用已有生成夹具，不使用私人聊天/账号截图。
- 仅用于本轮的无价值假密钥，例如 `echo-test-only-2468`；优先配本机HTTP测试端点。真实供应商测试只能由测试人填入自己的测试密钥。

从应用诊断记录数据目录；后续文件检查只针对这个测试实例的数据目录和 helper 缓存，不遍历用户所有应用数据或凭据。

安装包校验可在PowerShell中运行：

```powershell
$taskInstaller = 'C:\EchoLingoTest\EchoLingo_0.1.0_x64-setup.exe' # 替换为本轮包
Get-FileHash -Algorithm SHA256 -LiteralPath $taskInstaller
```

记录值必须与本轮发布资产校验值一致。文件名只是示例，不能据此认定已有该附件。

## 4. 原生helper受控冒烟

在已解锁的专用交互桌面，从仓库根目录运行已提供的脚本：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tests/windows-native-smoke.ps1
```

`Bypass`只作用于该次PowerShell进程，不能修改全机执行策略。企业策略阻止时记录实际错误，不绕过组织策略。

保存完整JSON、退出码和运行时间。其Unicode读写、受控选文、真实Ctrl+C fallback、密码控件拒绝及富文本恢复必须通过。只有脚本自己声明测试的项目算通过；截图、全局快捷键、多屏和真实浏览器仍要跑下面的用例。服务session-0、锁屏或焦点无法授予应记为失败/环境缺失，不能静默跳过再报通过。该脚本的更多边界见 `docs/native-testing.md`。

## 7. OCR语言包与系统限制

W-L01：从应用诊断记下 `ocrLanguages`、`ocrAvailable`、PowerShell版本与DPI模式。已安装英文OCR的系统识别英文；已安装中文OCR的系统识别中文并记录中英混排能力。不能把“Windows显示语言为中文”当作OCR中文语言包已存在的证明。

W-L02：在干净测试快照/专用账户中构造无可用OCR语言环境，不移除真实用户的日常语言设置。触发OCR应显示语言资源缺失的可操作提示，输入翻译/剪贴板翻译仍可用；不能无限尝试或悄悄上传云端。安装测试所需系统语言功能后重新诊断和重试，应可恢复。

W-L03：测试只安装一种OCR语言、缺中文资源但识别中文、WinRT不可用/企业脚本限制等情况。实际失败原因应与一般“无文本”区分。对未覆盖的Windows版本不能根据Win11通过而承诺支持。

## 9. 密钥库、API与错误处理

W-K01：新增本地测试服务，保存假密钥，完全退出后重开。UI显示“密钥已保存”，密码框不回填明文；请求通过受控端点确认认证头，报告中不记录完整值。检查本轮 `settings.json`、`history.json`、`.tmp` 和诊断输出，不应出现假密钥原文。

W-K02：修改密钥、留空编辑、删除密钥、删除服务分别操作。留空按UI约定保留；删除后凭据不再被使用。确认Windows凭据管理器的测试项随UI删除处理；不读取其他应用的密钥。

W-K03：凭据库拒绝/暂不可写、系统确认对话框抢焦点时保存。密钥失败明确报错，不能静默降级写JSON；返回应用后表单能恢复。保存过程中Esc/点遮罩/取消后立刻打开另一个编辑表单，旧异步任务不能关闭新表单或抹掉新输入。

端点用例优先使用可控本机fixture server，记录其版本、启动命令、监听地址及每条请求的路径/状态；只能监听loopback，不使用真实密钥。Fixture需能返回固定JSON、指定错误、延迟、超大响应和重定向。**没有可用fixture时记为环境缺失，不凭UI猜测这些用例已通过。** 已有Rust HTTP夹具可以验证协议，但不能替代装好的App端到端结果。

| W-A01 | OpenAI兼容：`http://127.0.0.1:<port>/v1`，带/不带斜杠，或完整`/v1/chat/completions` | 请求路径只出现一次后缀；模型名和原文正确，正文独立于system提示 |

## 10. 窗口、配置浮层与焦点

W-F01：浮窗默认在普通窗口上方；外点后隐藏，只有钉住时保留；Esc可隐藏浮窗并取消进行中的翻译。用户点击源App后正常输入，不出现键盘被EchoLingo吞掉。钉住决定外点保留，不改变默认置顶。

W-F02：打开服务表单，仅用键盘Tab/Shift+Tab循环、Enter提交、Esc关闭。焦点留在活动表单，背景按钮不能被点击或键盘触发；关闭后回原触发控件。取消、关闭、点遮罩均清空密码输入，不保留隐藏遮罩阻挡工作区。

W-F03：表单开着切换到其他App，触发输入/选文/截图快捷键再返回。不得悄悄丢弃表单输入、把焦点送到inert背景或让旧异步结果关闭新表单。可排队或有明确提示，行为必须一致。

W-F04：在最小尺寸、150%/200%缩放和深浅色下打开表单/确认删除。内容可滚动，保存和取消可达，没有黑屏/透明但拦截点击/内容裁掉。系统凭据库提示、Alt+Tab回来后重复检查。

## 11. 历史、原子写与数据故障

W-D01：保存多条历史，收藏/取消收藏、搜索、删除单条、清空全部，重启后状态一致。关闭历史后新任务不落盘；任务等待期间关闭历史也不再保存旧任务。清空全部同时使此前任务失效，不允许稍后重新填回。后端已有任务取消与当前隐私设置回归；此处仍需装好的 Windows App 验收。

W-D02：记录上限设置为50，产生超过50条；收藏优先保留策略与说明一致。所有项都是收藏时，不能无说明无限增长。检查长原文/多服务结果的启动、搜索与内存。

W-D03：先完成一次翻译，使正式 `history.json` 存在并记录其SHA-256。在另一个PowerShell进程以独占共享方式打开**本轮测试文件**，期间再翻译：

```powershell
$taskHistoryPath = 'C:\替换为诊断显示的测试数据目录\history.json'
$taskHistoryLock = [IO.File]::Open($taskHistoryPath, [IO.FileMode]::Open, [IO.FileAccess]::Read, [IO.FileShare]::None)
try { Read-Host '保持此锁；在应用内完成一次翻译后按 Enter 释放' }
finally { $taskHistoryLock.Dispose() }
```

预期：新译文仍返回；历史存储失败有可查warning；释放锁后旧正式文件仍在、可解析，既有收藏未丢；下一次写入恢复正常。Windows的实际文件共享行为以测试结果为准，若独占锁未阻止替换，记录并换用测试账户目录写权限故障；不要修改真实用户目录权限。

W-D04：保存设置/历史时在专用测试环境强制结束进程，再启动，重复至少10次；正式文件应为完整旧版本或新版本，不出现零字节/半JSON。正常退出前后查临时PNG是否清理。强制终止可跳过finally，因此残留文件也需记录和定义恢复策略。

W-D05：需要精确证明替换点故障时，应在测试构建注入“写前失败、sync后失败、MoveFileExW失败”并保存日志。普通随机杀进程没有撞到故障点，不能当作断电/全故障路径通过。

W-D06：损坏测试settings/history副本后启动。报错/使用默认的行为清楚，坏文件不静默被抹掉，且用户仍可到设置重新配置。现有代码可能对坏历史静默回空，作为已知风险记录，不把“没崩溃”当数据安全通过。

## 12. 退出、资源与性能预算

W-E01：点窗口关闭，仅隐藏而保留托盘；从托盘退出才完全结束。退出后任务管理器中无EchoLingo和该任务的helper/PowerShell进程；快捷键立即释放，重新启动可再次注册。

W-E02：截图框选中、OCR进行中、API等待中分别托盘退出。应有定义的结束行为，不能留下始终置顶的RegionPicker或孤立进程，不能在退出后意外改剪贴板。此项尤其验证子进程生命周期。

W-E03：连续20次启动/退出、100次选文、30次截图和取消混合；记录初末进程数、句柄、线程、内存、临时图数量。无持续单调增长或跨轮残留。

以下为工程预算，**没有实测前不宣传已达到**。ARM VM与x64分别记录，不能把宿主空闲内存当客体进程内存：

| 指标 | 目标/记录方式 |
|---|---|
| 包体 | 目标30MB级（不含外置WebView2/模型/语言资源）；同时记录首次下载总量、安装后占用，禁止只报小bootstrapper |
| 空闲常驻内存 | 目标进程树Private Working Set低于150MB；记录主进程+WebView2，启动稳定60秒后采样 |
| 快捷键可见响应 | 目标p95低于200ms；分别记录冷/热helper的“按键松开→框选出现/输入窗聚焦”，不能用API首字符时间替代 |
| 本地OCR | 目标1MP清晰图p95低于1.5秒；另外记录PowerShell启动/动态编译开销，首次与后续分开 |
| API翻译 | 独立记录连接/全文时间和端点；用固定延迟fixture测本地开销，真实云模型不用于证明UI延迟 |
| 稳定性 | 100次选文+30次截图后无崩溃/残留遮罩；内存和句柄无持续增长；未满足需说明原因 |

至少30个样本计算p50/p95。若预览版超预算，保留真实结果并列优化任务；不能因此删除失败样本或使用一次最快成绩。稳定版是否放宽预算需明确决策。

## 13. 发布门槛与产出

公开预览至少要求：两种环境有明确状态；安装/退出、输入、选文、截图翻译、静默OCR、剪贴板保护、密钥不明文落盘、默认协议和严重错误处理没有未解释的失败。缺少ARM VM可以不宣称ARM兼容；缺少x64实机时不能把VM/CI结果称为Windows全面验收。

稳定版需要完成实际x64桌面与混合DPI/多屏验收，关闭所有P0/P1，明确剩余P2；签名/更新分发策略独立验证。真实API未测、签名未做、部分应用取词不支持等都应在预览说明中可见。

本轮证据包应包含：填写的用例表、安装包校验、环境/诊断（脱敏）、smoke JSON、关键任务录屏、性能CSV/计算方法、未通过项及复测链接。测试记录引用同一commit和同一安装包，不能拼接不同版本的通过项当作一次完整验收。
