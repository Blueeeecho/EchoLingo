# macOS 取词来源一致性

## 架构约定

- 在请求入口固定来源应用与窗口，不能在队列等待后把新窗口当作原窗口。
- 来源凭据使用 CG 窗口身份或公开的 AX 焦点窗口身份。同一请求复核原凭据，不切换来源或证明方式。AX 对象通过绑定来源的有界、不透明令牌保留；未知、失效或身份不符的令牌均拒绝。
- 读取前后核对来源与控件；只对受约束的焦点建立路径执行一次只读正选区查询。权限、保护字段、安全输入、来源变化和查询错误均安全停止，不把错误当成空选区。
- 复制仍最多发送一次 Cmd+C。原剪贴板快照、稳定代际检测、有条件恢复和取消边界保持有效；不读取整篇文档、不强制激活其他应用，也不进行无界重试。
- 诊断只保留有界的枚举和数值元数据，不保存选文、剪贴板内容或窗口标题。进程内保留的最近失败用于区分尝试结果，不构成内容日志。

## 验证契约

原生夹具覆盖来源固定、窗口或控件变化、令牌生命周期、正选区恢复、受保护输入、查询失败和诊断边界。`tests/macos-native-self-test.sh` 必须检查这些结果，不能跳过失败项。

Python 合约测试只检查连接关系与安全边界，不代替 Swift 编译或原生执行。发布前必须通过 macOS 原生 CI；真实应用、权限状态、多显示器和快速连续操作仍需实机验收。系统调用的软预算不是严格墙钟时限，也不能据此保证所有应用均可取词。
